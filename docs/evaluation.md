# 评估体系与 PoC 计划

## 1. 评估原则

Game World KG 的评估不能只看三元组抽取 F1。

原因：

```text
一个图谱可能抽取准确，但不可玩。
一个 NPC 可能事实正确，但没有主观记忆。
一个任务可能文字合理，但不满足世界规则。
一个世界可能当前状态正确，但无法回放。
```

因此评估必须覆盖四类指标：

```text
世界一致性
动作可执行性
NPC 记忆正确性
玩家主观体验
系统延迟与稳定性
```

---

## 2. 核心评估维度

### 2.1 世界一致性

衡量系统是否保持世界事实稳定。

指标：

```text
实体失配率
关系冲突率
状态漂移率
canonical 污染率
replay 一致率
```

示例问题：

```text
钥匙到底在谁手上？
NPC 是否记住同一件事的不同版本？
谣言是否污染了世界真相？
```

---

### 2.2 动作可执行性

衡量 Affordance 是否正确。

指标：

```text
可行动作相关率
非法动作拦截率
遗漏合法动作率
动作前置条件正确率
动作后果可验证率
```

示例：

```text
玩家没有钥匙 → 不应出现“用钥匙开门”
玩家拥有通行令 → 应出现“出示通行令”
守卫不在场 → 不应出现“贿赂守卫”
```

---

### 2.3 NPC 记忆与角色一致性

衡量 NPC 是否基于自己知道的信息行动。

指标：

```text
记忆正确率
越权知识率
角色一致性评分
主观误解保留率
历史引用准确率
```

示例：

```text
NPC 不应知道玩家私下做过的事。
NPC 可以相信谣言，但不能把谣言当世界真相。
NPC 应记得玩家帮过自己。
```

---

### 2.4 任务生成质量

衡量任务是否从世界图谱中自然生长。

指标：

```text
任务依赖合法率
任务相关性
任务可完成率
奖励平衡度
世界因果可解释性
```

示例：

```text
村医缺草药 + 后山有草药 + 玩家有采集能力 → 生成采药任务
```

不合格任务：

```text
NPC 无缘无故要求玩家去杀 10 只狼
任务目标不存在
奖励无法兑现
前置条件不满足
```

---

### 2.5 系统性能

指标：

```text
POST /turn p50 / p95 延迟
图查询延迟
replay 1000 事件耗时
抽取耗时
Affordance 生成耗时
内存占用
```

MVP 不追求极致性能，但必须可观察。

## 3. 五个 PoC

### PoC 1：文本日志建图

目标：验证混合抽取是否可用。

输入：

```text
100 条战斗 / 交易 / 剧情日志
```

预期输出：

```text
事件
状态增量
节点
边
证据链
```

指标：

```text
schema 通过率
canonical 错误率
evidence 覆盖率
写入延迟
低置信降级率
```

验收标准：

```text
schema 通过率 >= 95%
evidence 覆盖率 >= 95%
canonical 错误率 <= 5%
```

---

### PoC 2：事件回放与回滚

目标：验证事件溯源设计。

输入：

```text
1000 条世界事件
```

预期输出：

```text
任意 turn 的世界快照
```

指标：

```text
回放正确率
回滚一致性
replay 耗时
LLM 隔离情况
```

验收标准：

```text
replay 正确率 = 100%
replay 过程中不得调用 LLM
回滚后状态与当时快照一致
```

---

### PoC 3：Affordance 校验器

目标：验证“当前可行动作”层。

输入：

```text
角色
地点
物品
规则
当前状态
```

预期输出：

```text
当前可执行动作集合
```

指标：

```text
动作相关率
非法动作拦截率
遗漏合法动作率
p95 响应时间
```

验收标准：

```text
非法动作拦截率 >= 95%
动作相关率 >= 85%
p95 < 500ms，本地 MVP 可放宽
```

---

### PoC 4：NPC 记忆问答

目标：验证 MemoryGraph 的收益。

输入：

```text
1 个 NPC
20 轮互动历史
若干 canonical 事实、npc 记忆、rumor
```

预期输出：

```text
带记忆引用的 NPC 回答
```

指标：

```text
记忆正确率
越权知识率
角色一致性
幻觉率
人评偏好
```

验收标准：

```text
NPC 不知道未见过的私密事件
NPC 能引用自己经历过的事件
NPC 可基于 rumor 误解，但不能改变 canonical
```

---

### PoC 5：任务链生成

目标：验证任务从世界矛盾中自然生长。

输入：

```text
玩家画像
世界状态
NPC 目标
资源缺口
任务模板
```

预期输出：

```text
3 条任务候选
每条任务的依赖图
合法性说明
奖励和失败后果
```

指标：

```text
任务依赖合法率
相关性
可完成性
奖励平衡
世界原因解释质量
```

验收标准：

```text
任务依赖合法率 >= 85%
每个任务必须能追溯到图谱中的矛盾或需求
```

## 4. MVP 回归测试集

### 4.1 城门 Demo 基础测试

初始状态：

```text
玩家位于村口
铁门锁住
守卫位于村口
玩家拥有通行令
玩家没有银钥匙
守卫信任玩家 = 3
```

测试：

```text
1. 玩家没有钥匙 → 不能用钥匙开门
2. 玩家拥有通行令 → 可以出示通行令
3. 守卫信任不足 5 → 不会主动放行
4. 玩家出示通行令 → 守卫信任 +2
5. 守卫信任达到 5 → 解锁请求放行
6. 玩家贿赂守卫 → 信任可能上升，但声望下降
7. 玩家偷钥匙失败 → 守卫敌意上升
8. 回滚到第 1 回合 → 通行令仍在玩家手中
```

---

### 4.2 Scope 测试

输入：

```text
村里有人说玩家偷了钥匙。
```

预期：

```text
写入 rumor
不改变 canonical key.holder
```

输入：

```text
守卫怀疑玩家偷了钥匙。
```

预期：

```text
写入 npc.guard SUSPECTS player
不改变 canonical
```

输入：

```text
系统事件：玩家从桌上拿起钥匙。
```

预期：

```text
写入 canonical TRANSFER_ITEM
key.holder = player
```

---

### 4.3 LLM 权限测试

输入：

```text
玩家说：我掏出一把并不存在的银钥匙打开铁门。
```

预期：

```text
LLM 可以解析为候选行动
RuleEngine 必须拒绝
不得写入 canonical open_gate
```

---

### 4.4 NPC 越权知识测试

前置：

```text
玩家私下把钥匙藏到井边。
守卫没有看到。
没有谣言传播。
```

询问守卫：

```text
你知道钥匙在哪里吗？
```

预期：

```text
守卫不知道
不得回答“在井边”
```

## 5. 对照组设计

为了证明 KG 有价值，需要对照组。

### Baseline A：纯 LLM 长上下文

```text
只给历史对话，不给结构化图谱。
```

对比指标：

```text
状态漂移率
NPC 越权知识率
任务非法率
```

### Baseline B：摘要记忆

```text
只给剧情摘要，不给 EventLog 和 WorldGraph。
```

对比指标：

```text
细节记忆正确率
因果解释能力
回滚能力
```

### Baseline C：向量 RAG

```text
只做向量检索，不做图谱和规则。
```

对比指标：

```text
关系推理正确率
动作前置条件正确率
任务依赖合法率
```

目标不是证明 KG 永远最好，而是证明：

```text
在长期一致性、动作合法性、NPC 记忆、因果解释上，KG 明显优于纯 LLM / 摘要 / RAG。
```

## 6. 评估数据采集

### 6.1 自动日志

每次 turn 保存：

```text
player_input
action_parse_result
rule_result
events
state_deltas
graph_updates
affordances
narration
latency
```

### 6.2 证据链

所有抽取结果保存：

```text
source_id
span_start
span_end
text
extractor
confidence
scope
```

### 6.3 人工标注

标注内容：

```text
事实是否正确
scope 是否正确
NPC 是否越权知道
动作是否合理
任务是否有世界原因
```

### 6.4 玩家主观问卷

问题：

```text
你是否感觉世界记得你的行动？
NPC 是否像有自己的记忆？
当前可行动作是否合理？
任务是否像从世界中自然出现？
```

## 7. 推荐第一阶段验收门槛

MVP 验收：

```text
事件 replay 正确率 = 100%
非法动作拦截率 >= 90%
evidence 覆盖率 >= 90%
NPC 越权知识率 <= 10%
canonical 污染率 <= 5%
```

Beta 验收：

```text
非法动作拦截率 >= 95%
任务依赖合法率 >= 85%
NPC 记忆正确率明显优于摘要基线
玩家主观“世界记得我”评分高于纯 LLM 基线
```

---

## 8. 最重要的判断

第一阶段不要以“剧情是否好看”为主要验收标准。

更重要的是验证：

```text
世界是否稳定
事件是否可回放
状态是否可解释
NPC 是否知道自己该知道的事
玩家当前可做的事是否由世界结构推导
```

如果这些成立，再追求叙事质量、世界生成、多题材模板和 UI。
