# 游戏通用知识图谱研究报告

## 1. 核心结论

游戏通用知识图谱不应只是“人物、地点、物品”的静态百科图，而应作为 AI 游戏世界的**可执行世界结构层**。

```text
Game World Knowledge Graph
= World Ontology
+ Static World Graph
+ Dynamic State Graph
+ Affordance Graph
+ Event / Quest Graph
+ Narrative Memory Graph
```

它的目标是支撑：

- 世界长期一致
- NPC 不失忆
- 玩家行动有持久后果
- 任务从世界矛盾中自然生长
- 生成内容受规则约束
- 世界可以自运行、回放、回滚和审计

一句话：

> KG 是 AI 生成式游戏的骨架，LLM 是血肉，规则引擎是物理法则。

---

## 2. 现有方向梳理

### 2.1 叙事知识图谱

叙事 KG 主要解决长篇故事一致性问题，例如人物关系、地点、事件、物品、伏笔不混乱。

适合解决：

- 角色不突然失忆
- 前后设定不矛盾
- 伏笔可追踪
- 历史事件可被重新引用

不足：

- 更偏故事，不天然支持玩家交互
- 通常缺少状态变化、可供性、规则判定

### 2.2 交互小说 / 文本游戏图谱

文本游戏更接近目标，因为它需要把“故事事实”变成“可交互世界”。

普通小说图谱只需要知道：

```text
钥匙 --位于--> 房间
门 --连接--> 走廊
```

游戏图谱还必须知道：

```text
钥匙 --可用于--> 打开门
门 --状态--> 锁住
玩家 --拥有--> 钥匙
玩家 --当前位置--> 走廊
```

关键概念是 **Affordance**，即某个对象在当前状态下能被怎样操作。

### 2.3 动态知识图谱

游戏状态会随着玩家行动不断变化，所以游戏 KG 必须支持图更新操作：

```text
ADD_NODE
ADD_EDGE
UPDATE_ATTR
REMOVE_EDGE
MOVE_ENTITY
CHANGE_STATE
START_EVENT
END_EVENT
INCREMENT_RELATION
```

如果图谱只在开局生成一次，它只能做设定库，不能支撑游戏运行。

### 2.4 任务与对话生成

任务不应随机生成，而应从世界图谱中的不平衡关系自然生长：

```text
NPC 缺少资源
地点存在危险
玩家拥有能力
NPC 信任玩家
```

因此生成任务的本质是：从世界矛盾中选择一个可被玩家介入的结构。

### 2.5 游戏本体论

通用游戏 KG 需要先定义类型系统，否则 LLM 抽取会混乱。

至少需要这些类型：

```text
Character
Location
Item
Faction
Rule
Event
Quest
Ability
Resource
State
Action
Memory
Relationship
```

理论原则：

> Ontology first, KG second, LLM extraction third.

## 3. 建议理论框架：Game World Graph

### 3.1 World Ontology：世界本体层

定义游戏世界中有哪些实体类型、关系类型、状态类型和行动类型。

职责：

- 约束 LLM 抽取结果
- 统一不同题材世界的通用结构
- 防止实体类型混乱

### 3.2 Static World Graph：静态世界图

存稳定设定。

示例：

```text
青云宗 --位于--> 青云山
医院 --拥有规则--> 禁止喧哗
钥匙 --可开启--> 铁门
守卫 --属于--> 城门卫队
```

它类似世界百科，但不是全部。

### 3.3 Dynamic State Graph：动态状态图

存当前状态。

示例：

```text
玩家 --位于--> 村口
钥匙 --持有者--> 玩家
铁门 --状态--> 锁住
守卫 --态度--> 警惕
```

这层更像游戏存档。

### 3.4 Affordance Graph：可供性图

回答“玩家当前能做什么”。

示例：

```text
铁门：查看 / 敲门 / 用钥匙打开 / 撬锁 / 撞开
守卫：交谈 / 贿赂 / 威胁 / 出示通行令
药品：使用 / 交易 / 偷取 / 申请领取
```

这是区分游戏 KG 和小说 KG 的关键层。

### 3.5 Event / Quest Graph：事件任务图

存事件的前置、触发、后果和因果链。

示例：

```text
任务A --需要--> 玩家知道黑石
任务A --需要--> 陈山信任玩家
任务A --奖励--> 青云宗功绩
任务A --失败后果--> 黑石被村长家截胡
```

### 3.6 Narrative Memory Graph：叙事记忆图

存发生过的事，以及它对角色认知和关系的影响。

示例：

```text
第12回合：韩茜质疑张临
第35回合：韩茜认可采购透明
第42回合：韩茜成为资源监督人
```

需要区分：

```text
canonical：世界真相
player：玩家已知
npc：某个 NPC 的记忆
faction：某个势力认知
rumor：传闻或误解
```

## 4. 关键设计判断

### 4.1 Event Log 是真值源

当前状态不应由 LLM 直接改写，而应由事件日志投影得到。

```text
初始状态
+ 事件1
+ 事件2
+ 事件3
= 当前状态
```

好处：

- 可回放
- 可回滚
- 可解释
- 可审计
- 可重建图谱
- 可防止 LLM 乱改状态

### 4.2 世界真相与主观记忆分离

同一个事件在不同范围内可能有不同版本。

示例：

```text
canonical：玩家没有偷钥匙
npc.guard：守卫怀疑玩家知道钥匙下落
rumor：村里传闻玩家和盗贼有联系
```

这能支持误会、谣言、秘密、偏见和 NPC 自运行。

### 4.3 Affordance 是游戏感来源

没有 Affordance，系统只能讲故事；有 Affordance，系统才能让玩家真正交互。

Affordance 应由规则和图谱推导，不应该完全由 LLM 编造。

### 4.4 LLM 只负责叙事与候选抽取

LLM 的职责：

- 解析玩家自然语言行动
- 生成叙事文本
- 生成 NPC 对话
- 抽取候选事实
- 补全世界细节

LLM 不应直接写入 canonical 状态。

### 4.5 规则引擎负责合法性

规则引擎负责判断：

- 玩家是否在可交互距离内
- 是否持有所需物品
- 是否拥有权限
- NPC 是否知道某件事
- 行动是否违反世界规则
- 状态变化是否允许

---

## 5. 通用游戏 KG 的应用场景

### 5.1 AI 叙事游戏

用 KG 约束 LLM，解决长线剧情漂移问题。

### 5.2 NPC 记忆与对话

NPC 根据自己的记忆、误解、阵营认知进行对话，而不是全知全能。

### 5.3 动态任务生成

任务从世界矛盾中自然出现，而不是随机模板。

### 5.4 世界自运行

NPC、势力、事件可以根据目标和状态推进。

### 5.5 玩家行为审计

所有状态变化都能解释来源：哪一回合、什么事件、什么证据。

### 5.6 多题材世界模板

地铁求生、修仙、海洋、末日、赛博都市都可以复用同一套底层结构，只换 WorldSpec、RuleSet、Ontology 扩展。

---

## 6. 推荐方向

本项目的理论方向应定义为：

> 面向 AI 生成式游戏的动态知识图谱，用于统一表示世界本体、静态设定、动态状态、可交互 affordance、事件任务逻辑和叙事记忆，为 LLM 叙事、NPC 行为、规则判定和程序化内容生成提供结构化支撑。

不建议只做：

- 文本向量检索
- 人物关系图
- 剧情摘要
- 静态世界百科
- 纯 LLM 跑团

推荐做：

```text
事件溯源
动态图谱
Affordance 推导
NPC 主观记忆
规则引擎
LLM 叙事与抽取
```
